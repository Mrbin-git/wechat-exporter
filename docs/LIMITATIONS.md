# 已知限制与取舍决策（1.0.0）

本文记录 1.0.0 明确**不做**的事、为什么不做，以及将来什么条件下会做。面向使用者与后续维护者：
遇到"为什么不支持 X"时，先看这里，再看 [FAQ](FAQ.md) 与 [RISKS](RISKS.md)。

| 限制 | 现状 | 为什么这次不做 | 后续触发条件 |
| --- | --- | --- | --- |
| SILK 语音不转码 | 保留原始 `.silk` 数据，页面标注"未找到本地文件"或给出原始文件链接 | ① 桌面端多数语音根本没有本地文件，转码收益低；② 可靠的 SILK→PCM 实现多带 C 依赖/专利与许可问题，塞进 exe 会显著增大体积与误报率 | 出现许可证清晰的纯 Python/可再分发实现，且用户反馈强烈时，作为**可选**后处理 |
| HEVC（`.wxgf`）不解码 | 原样保留文件，HTML 中给可点击链接 | 需要 HEVC 解码器（ffmpeg 或系统解码链），自带一份会让包体再涨十几 MB 且涉及专利授权；本次构建机也没有 ffmpeg | 用户自行安装 ffmpeg 后，工具可探测并调用它转码（不打包 ffmpeg） |
| 只支持微信 4.x | 3.x 明确报错退出 | 3.x 的数据库结构、密钥派生、内存特征与 4.x 完全不同，需要另一套读写与解密实现；没有可靠样本时不猜 | 有 3.x 用户提供可复现样本，且不影响 4.x 维护成本 |
| 不支持企业微信（WeCom） | 不探测、不导出 | 数据目录、加密方式与个人微信不同，属于另一个产品 | 单独立项，不混在本工具里 |
| 数十 GB 大库未压测 | 逐页 AES+HMAC 解密，时间随数据量线性增长；FAQ 给出量级估算 | 缺少真实大样本；盲目优化（并行/分片）容易引入一致性 bug | 收到"单个账号 > 20 GB"的真实耗时数据后，再做并行解密与进度反馈 |
| exe 未签名 | 首次运行可能触发 SmartScreen/杀软提示 | 代码签名证书每年数百到数千元，个人项目不承担；且签名不改变程序行为 | 有持续分发需求时再购买，届时同步更新 SHA256 与说明 |
| 未做 Windows 10 实机 / 杀软实测 | 仅在 Windows 11 + Defender 上验证 | 手上没有 Win10 实机与其他杀软环境；PyInstaller 产物被误报是已知行业现象 | 拿到实机或用户误报样本后补测，并把结果写进 [TESTREPORT](TESTREPORT.md) |
| 构建机：vendor 个别目录权限异常 | 沙箱内重建可能报 `Access denied`（本机 `vendor\openpyxl`、`PIL`、`et_xmlfile` 等 6 个目录权限被保护） | 这些目录的所有者是当前用户，**普通用户直接构建不受影响**；受限于 DSH 沙箱的受限令牌时才读不到 | 在受限沙箱里重建时用完整权限运行一次，或把 vendor 依赖重装一遍（新目录会继承正常权限） |

## 明确的非目标（不打算做）

- **不上传、不联网**：所有解密与导出都在本机完成，没有云端备份/同步功能。
- **不做聊天记录编辑/伪造**：只读导出，不提供修改数据库或伪造消息的功能。
- **不做"导出他人聊天记录"的便利化**：工具面向"导出本人设备上本人账号"的场景。
- **不做增量同步**：每次导出都是完整快照，避免引入状态与去重逻辑的复杂度。
