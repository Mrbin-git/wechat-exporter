## 一、这个工具在技术上做了什么

用一句话说清性质：**在你自己已登录的微信客户端正在运行时，从该进程的内存中取出它自己派生出来的数据库密钥，用它解开本机上属于你自己的数据库副本。**

拆开看三个动作，风险等级不同：

| 动作 | 性质 | 风险点 |
| --- | --- | --- |
| 读注册表与 `.ini` 找路径 | 普通的配置读取 | 无 |
| 读 `Weixin.exe` 进程内存 | **跨进程内存读取**（`OpenProcess` + `ReadProcessMemory`） | 技术上与很多恶意软件的行为特征重合；需同一用户/同权限才成功 |
| 用密钥解密数据库 / `.dat` 文件 | 对**本地文件副本**做密码学运算 | 不触碰原文件；临时副本是明文，需及时清理 |

### 内存读取这一步，为什么必须做

微信 4.x 的数据库由 SQLCipher 加密，密钥不是写死在配置文件里的密码，而是客户端在登录后根据账号信息派生、并常驻在进程内存中的 32 字节数据。工具的做法是：

1. 在 `Weixin.exe` 的内存里按一条已知的指令特征（`48 BA` 后接 8 字节立即数的连续模式，业界称 YaRA 特征）定位持有密钥的代码区域；
2. 顺着指针取出候选的 32 字节缓冲区；
3. 每个候选与 `Weixin.dll` 里内嵌的 internal key 做异或，得到候选 passphrase；
4. 用数据库第 1 页末尾的 HMAC-SHA512 校验——**只有真正正确的密钥才能通过**，所以不会"猜"出一个能用的错密钥。

关键含义：

- **它没有破解任何密码学算法。** 密钥本来就是明文躺在你自己的进程内存里，工具只是把它读出来。
- **它不绕过登录。** 没有登录，内存里就没有密钥；工具也**不会**去模拟登录、拦截网络包或伪造握手。
- **它只对"当前用户可访问"的内存生效。** 换用户、换会话、提权运行，都会失败——这不是 bug，是 Windows 的进程隔离在起作用。

### 为什么杀软会误报

PyInstaller 打包 + 无代码签名 + 跨进程读内存 + 批量解密文件，这四条叠加起来，与"信息窃取类"样本的静态/行为特征高度相似。因此出现 SmartScreen 拦截、启发式告警是**可预期**的。判断依据应当是来源可信度与源码可审计性，而不是"有没有报警"。

## 二、技术风险清单

| # | 风险 | 触发条件 | 影响 | 缓解措施 |
| --- | --- | --- | --- | --- |
| T1 | **微信版本升级导致取密钥失效** | 微信 4.x 大版本更新，内存特征或 DLL 内嵌 key 改变 | 自动取密钥失败，导不了 | 见第三节兼容矩阵；保留旧版安装包；等待工具适配；核心模块支持手动密钥作为兜底 |
| T2 | **跨用户/跨权限读取内存失败** | 工具以管理员身份运行；微信在另一 Windows 用户下；UAC 提升不一致 | 报"未检测到进程"或"找不到密钥特征" | 用**同一个普通用户**双击运行；不要"以管理员身份运行" |
| T3 | **解密期间微信并发写库** | 导出时微信仍在大量收发消息 | 少数页 HMAC 校验失败，个别消息缺失或乱码 | 导出期间减少微信活动；工具对坏页只做告警、不中断；失败可重试 |
| T4 | **临时明文副本残留** | 崩溃/断电/强杀进程；手动设了 `WEXPORT_KEEP_WORK=1` | `%LOCALAPPDATA%\WeChatExporter\work\` 留下明文数据库 | 正常结束（含报错）会自动删除；定期检查并手动清理该目录；不要在排查后忘记删 |
| T5 | **密钥缓存被同机他人读取** | 同一 Windows 账户被他人共用；未设登录密码 | 他人可解开 `keys.dat` 拿到密钥 | DPAPI 绑定当前账户；给 Windows 账户设密码；不用时删 `keys.dat` |
| T6 | **导出文件二次泄露** | 导出结果被上传网盘、发给他人、留在共享目录 | 全部聊天内容（含对方隐私）外泄 | 导出到加密盘/BitLocker 卷；导出后加密压缩并设密码；及时删除中间副本 |
| T7 | **杀软拦截 / 隔离 exe** | 启发式引擎判定 | 程序无法启动，或运行中被终止 | 添加信任；自行从源码构建；对产物做哈希公示 |
| T8 | **手动密钥泄露** | 把 64 位十六进制密钥贴到聊天窗口、工单、截图里 | 拿到密钥 + 数据库文件即可解密全部记录 | 密钥只在工具内使用；任何情况下不要外发；泄露后需修改微信密码（**注意：改密码不必然更换数据库密钥**） |
| T9 | **大账号磁盘占满** | 解密副本 + 媒体副本同时落盘 | 系统盘写满，导出中断 | 把输出目录放到数据盘；先只导文字（不勾媒体）；预留与数据目录相当的空间 |
| T10 | **长路径/特殊字符写文件失败** | 会话名极长，或备注名含 `/ : * ? " < > \|` | 个别会话导出失败 | 工具会过滤非法字符；必要时改用短备注名或较短输出路径 |
| T11 | **HEVC 图片无法显示** | 原图为 `wxgf` 容器封装的 HEVC | 导出的是 `.wxgf` 原文件，浏览器打不开 | 见 [MEDIA.md](MEDIA.md)；用支持 HEVC 的外部工具查看 |
| T12 | **语音缺失** | 桌面端未落地语音文件 | 页面标注"未找到本地文件" | 无解，属微信客户端行为；需在微信内或手机端收听 |

## 四、法律与合规边界（事实描述）

以下仅陈述事实与常见法律框架，**不构成法律意见**。具体到你的情形，请咨询执业律师。

### 4.1 你导出的是"谁的"数据

聊天记录在法律关系上通常涉及**双方**：你发的、对方发的，都在同一个数据库里。因此：

- 你对**自己账号**的数据享有查阅、复制自己信息的权利（例如中国《个人信息保护法》第 45 条规定的个人查阅、复制权）；
- 但记录中**对方的**发言、昵称、头像、手机号、住址同样属于对方的个人信息，甚至可能属于敏感个人信息；
- 因此"我有权导出我的记录"不等于"我有权公开对方的发言"。

### 4.2 中国法下的主要相关规范（背景）

| 规范 | 与本工具相关的要点 |
| --- | --- |
| 《个人信息保护法》 | 处理个人信息需有合法性基础；第 45 条赋予个人查阅、复制权；第 10 条禁止非法收集、使用、加工、传输他人个人信息 |
| 《民法典》人格权编 | 隐私权与个人信息保护；第 1032–1039 条涉及私密信息、公开他人私密信息的责任 |
| 《数据安全法》《网络安全法》 | 不得从事非法侵入他人网络、干扰网络正常功能、窃取网络数据等危害网络安全的活动 |
| 《刑法》第 285 条 | 非法获取计算机信息系统数据罪——**"未经授权访问他人计算机系统"是红线**，与"导出自己账号"有本质区别 |
| 《治安管理处罚法》 | 偷窥、偷拍、窃听、散布他人隐私的处罚 |

判断的关键从来不是"用了什么工具"，而是：**数据属于谁、你有没有获得授权、导出后用于什么**。在**自己的设备、自己的账号、自己知情同意**的前提下做备份，与"在别人电脑上装个工具把记录拷走"是两件性质完全不同的事。

### 4.3 美国 DMCA 的技术背景

美国《数字千年版权法》第 **1201** 条禁止"规避有效控制访问作品的技术保护措施"。该条设有例外，由美国版权局每三年一次的规则制定程序（rulemaking）确定，历史上曾就旧软件保存、设备越狱、维修等场景设定有限例外；**但这些例外并未普遍覆盖"聊天记录导出工具"这一类别**。因此在部分司法辖区，此类工具的**分发或使用**存在被主张构成规避的风险，具体认定高度依赖事实与法院见解。

事实层面的补充：本工具不复制、不传播微信客户端的代码或资源，不绕过网络侧的身份认证，不做协议逆向以伪造请求，只在本地读取用户自己设备上的数据文件。**这不等同于法律上必然合规**——是否合规由当地法律与具体使用场景决定。

### 4.4 腾讯的服务条款

《腾讯微信软件许可及服务协议》等文件通常包含以下类型的约定（请以腾讯官方最新文本为准）：不得对软件进行反向工程、反向汇编、反向编译；不得使用外挂、第三方工具以非官方允许的方式访问或修改微信数据与功能。用户导出自己的聊天记录是否落入某一具体条款，属于**条款解释问题**，工具作者无法代替腾讯或法院作出判断。

**可能的实际后果**（事实陈述，非威胁）：账号被限制功能、被封禁；企业环境中被认定为违反内部 IT 政策。是否发生取决于腾讯的判断，本工具不做任何规避性设计（例如不伪造客户端指纹、不隐藏行为）。

### 4.5 作为证据使用

导出的 HTML/CSV 属于**电子数据的转化形式**，其证明力通常弱于原始载体：

- 民事诉讼中，法院通常要求提供**原始存储介质**或说明来源与提取过程；单方面导出的文件可能被质疑完整性、真实性；
- 更稳妥的做法是：保留原始手机/电脑、请**公证处**做证据保全公证、或委托**司法鉴定**机构做电子数据鉴定；
- 本工具产出的文件可作为整理、检索、提交的载体，但**不构成任何形式的证据效力保证**，也不提供哈希固化、时间戳、签名等取证级功能。

### 4.6 其他司法辖区

欧盟 GDPR 框架下，本人数据的导出属于数据主体权利（访问权/可携带权）范畴，但涉及他人数据时仍需合法基础；其他辖区各有规定。**跨境传输、公开发布他人聊天内容**在任何辖区都是高风险行为。
